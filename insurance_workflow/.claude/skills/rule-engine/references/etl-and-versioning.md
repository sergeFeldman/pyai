# Rule ETL and Versioning

Read this when adding or editing rule data, adding a rule domain, or changing `src/etl/rule_etl.py`.

## Files

- `data/in/<domain>_rules.json`: raw rule definitions, edited by people. No `domain` or `metadata` fields; `kind` is optional and ignored for type detection.
- `data/out/<domain>_rules.json`: versioned output with every version of every rule, generated by the ETL. The app and the MCP server load these at startup. Never edit them by hand.
- `config/etl.yaml`: one entry per domain. The entry key is the domain name stamped onto every rule; it holds `input_file_path`, `output_file_path`, and `updated_by`.
- `config/storage.yaml`: `rule_registry` and `rule_registry_policy` point the app at the output files. A new domain file needs an entry here and in the `load_from` call in `src/app/dependencies.py`.

## Run

From the project root, as a separate process (never inside the running app, because the ETL calls `load()` on the registry singleton):

```bash
PYTHONPATH=src python src/etl/rule_etl.py
```

Restart the app afterwards; the registry is loaded only at startup.

## Versioning rules

For each domain, `RuleEtl.run()`:

1. Loads the existing output file into the registry (empty on the first run).
2. For each raw rule, detects its type and keeps only that type's fields, then:
   - new id: added at version 0, `created_by = updated_by`;
   - existing id with any business field different from the latest version (`is_changed`, all fields except `metadata`, including priority, effective dates, input, output, and reason): added as a new version with `metadata.bump(updated_by)`;
   - unchanged: skipped.
3. Writes all versions back to the output file, sorted by id then version descending.

Rules are never deleted. To retire a rule, set its `effective_to` to a past timestamp and run the ETL; the new version becomes inactive and history is kept.

## Examples

- Normal: raising `ca_min_amount`'s threshold from `"1000"` to `"1500"` in `data/in` and running the ETL adds version N+1; `GET /rules/history/claim_appeal/ca_min_amount` shows `threshold` in `changed_fields`.
- Edge: running the ETL twice with no input change adds no versions.
- Edge: a raw rule with neither decision fields nor `match_keys`/`output_values` makes `detect_type` raise `ValueError` and stops the run.
